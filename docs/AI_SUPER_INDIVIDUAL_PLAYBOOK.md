# DrawnKit：AI 时代超级个体工作范式报告

## 1. 工作原则

项目采用“一个人定义目标，多 Agent 并行发现盲区，自动化系统承担重复劳动”的工作方式。产品 Agent 负责定位和取舍，安全 Agent 建立可信边界，增长 Agent 设计获客与运营闭环，工程 Agent 把要求转化为可测试、可发布、可回滚的系统。

所有决策围绕一个首月指标：完成至少一笔真实的 1 美元订单。页面数量、功能数量和访问量都不是目标本身。

## 2. 产品判断

DrawnKit 不销售“20 条神秘 Prompt”，而是销售可持续复用的一致性视觉系统。用户更强的需求是让一组故事、课程或产品插图保持稳定的色彩、线条、纸张质感和角色比例。

免费层负责证明价值：无需注册即可使用三套完整配方。付费层以一次性 1 美元提供 20 套完整配方、模型适配、失败模式清单、Markdown/JSON 文件和当前大版本更新。

## 3. 安全边界

- Waffo Merchant ID、私钥和产品 ID 仅存在于 Vercel 服务端环境变量。
- Checkout 的产品、币种、价格与成功地址由服务端固定，浏览器不能覆盖。
- 支付成功回跳页不授予权益；验签后的生产 Webhook 才是付款事实来源。
- Webhook 必须读取原始正文、验证 RSA 签名、环境、Store、币种和金额。
- 正式收款前必须接入持久化权益库，对 event.id 建唯一索引，处理重复、乱序和退款。
- 数字包不得放在 public 目录；交付使用短时、限次、可撤销下载令牌。
- 分析系统不采集 Prompt 原文、邮箱、完整订单号或支付信息。
- GitHub、Vercel 和 Waffo 使用 MFA、最小权限和定期密钥轮换。

当前支付凭据缺失时，Checkout 返回 503 并明确告知用户，免费产品和 SEO 页面继续工作。这是故障隔离，不是静默失败。

## 4. 崩溃与故障模型

| 场景 | 处理方式 |
|---|---|
| Waffo 超时、429、5xx | 12 秒超时、按钮防重复、清晰重试提示，不假定已付款 |
| 环境变量缺失 | 关闭付款能力，保留免费生成器和内容页 |
| Webhook 重复或乱序 | event.id 幂等、订单状态单调迁移 |
| 权益库不可用 | Webhook 返回非 2xx 让 Waffo 重试，不确认未完成的交付 |
| 图片失败 | 固定比例容器避免布局跳动，文本内容仍可阅读 |
| JavaScript 失败 | 核心价值、样例、定价和 SEO 内容由服务端输出 |
| 分析服务失败 | 不阻断生成、复制或结账 |
| 流量尖峰 | 主要页面静态生成并由 CDN 缓存，API 限流并设置超时 |

P0 事故包括全站不可用、密钥泄漏和付款成功未交付。发生后立即隐藏购买入口、停止推广、回滚或修复，并对受影响订单主动补发或退款。

## 5. 性能范式

预算为移动端 LCP 小于 2.5 秒、INP 小于 200ms、CLS 小于 0.1。首屏只优先加载关键样图，其余图片懒加载；原始 2–3MB PNG 已转换为压缩 JPEG，生产环境继续由 Next Image 生成响应式格式。风格页静态生成，避免运行时数据库和瀑布请求。

每次发布执行 lint、TypeScript、生产构建和浏览器验收；移动端必须检查横向溢出，生产环境必须扫描控制台、404、5xx 和安全响应头。

## 6. 增长与自传播

增长循环为：

访问真实样例 → 免费生成 → 复制并获得结果 → 分享风格卡 → 新用户 Remix → 体验付费风格 → 1 美元购买。

P1 分享页只公开简化配方与风格结果，绝不携带订单、支付 Session、下载令牌或完整付费 Prompt。推荐激励首月采用“好友多解锁一个免费风格”，不采用现金分佣，因为 1 美元客单价无法覆盖佣金和欺诈成本。

首月渠道顺序：定向创作者触达、X 前后对比、Indie Hackers 构建日志、Reddit 方法帖、GitHub Demo、优质 AI 目录、Google/Bing 长尾 SEO。不投付费广告，不买低质外链，不伪造倒计时、销量或评价。

## 7. SEO 工作流

每个风格页必须拥有独立样图、媒介说明、使用场景、失败模式、模型建议和相关风格内链。禁止用换标题的方式制造数百个近重复页面。

内容发布流程：确认搜索意图 → 真实生成测试 → 至少三个独有样例 → 写失败模式与修复 → 内链 Generator、Pricing 和风格页 → 结构化数据 → 移动端与分享预览 → 提交索引 → 7/14/28 天复盘。

核心主题围绕 consistent illustration style、style drift、hand-drawn AI prompt、storybook、crayon、ink wash、teacher illustration 和 newsletter illustration。

## 8. 数据与决策阈值

核心事件为 page_view、generator_started、prompt_generated、prompt_copied、purchase_cta_clicked、checkout_redirected、purchase_completed、download_completed、share_created 和 remix_started。

- 20 个高相关 Session，生成器启动率低于 15%：改 Hero 承诺和首屏 Demo。
- 生成成功率低于 90%：暂停引流，先修产品。
- 生成后复制率低于 35%：改输出质量和结果呈现。
- 30 个激活用户，购买点击率低于 3%：强化商品内容与真实对比。
- 10 次 Checkout 到达，支付成功率低于 30%：检查信任、移动端、币种和结账故障。
- 100 个高相关访客仍无订单：进行至少 5 次访谈，不能只继续堆 SEO。
- 任一核心错误率超过 2%：暂停推广。

前 100 个 Session 不做低样本 A/B 测试；采用顺序实验，每次只修改一个变量并记录日期。

## 9. 运营全流程

每日 20 分钟体检：首页、生成器和 Checkout 合成探测；订单与权益对账；Webhook 积压；404/5xx；Web Vitals；客服；索引状态和流量来源质量。

每周复盘渠道 Cohort、关键词落地页、最高退出点、退款投诉、死链、依赖安全和备份恢复，选定唯一一个增长假设。

每月导出订单和税务记录，复测模型兼容性，发布资产版本和 Changelog，审查隐私/许可证，决定渠道去留和是否调整价格。

客服 SLA：付款和交付问题 4 小时内，一般问题 24 小时内。处理顺序永远是先恢复用户权益或退款，再调查内部根因。

## 10. 发布、回滚与恢复

发布链路为本地质量门 → GitHub `main` → GitHub Actions → Vercel 构建 → 生产部署 → 浏览器冒烟 → 日志观察。每次生产发布保留上一稳定部署，可通过 Vercel 即时回滚。

正式开启付款前的 No-Go 清单：

- Waffo 生产 Merchant ID 与私钥未配置。
- 产品没有 publish 并 active。
- 没有持久化权益库和 Webhook 幂等。
- 没有真实 1 美元付款和退款演练。
- 任何私钥进入客户端、日志或 Git 历史。
- 任何实现凭回跳 URL 直接解锁。

这些条件任一未满足，站点可以上线并获客，但购买能力必须保持安全关闭。
